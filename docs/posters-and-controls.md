# 封面、手机交互与账号请求

## 封面加载

图片地址仍来自已配置目录，不生成图片地址。页面使用 IntersectionObserver，仅请求当前视口及附近 180 px 的图片，最多四张并发；首行标记高优先级，固定比例占位，异步解码。已显示卡片保持 DOM，观看进度更新不重建最近观看图片。

加载失败或超过八秒后尝试备用图片，最多四个地址；失败地址冷却一分钟。合并备用图片必须核对片名、年份、季数和作品类型，不能借用其他季或翻拍版封面。失败时保留卡片并显示“暂无封面”。

0.6.6 为失效图片增加独立的封面补全请求。先查已有片源目录，再查询最多三个已配置来源，每个来源只查第一页，总时限九秒。只采纳通过作品身份核对的真实图片地址；补全结果进入原目录缓存，避免每次打开重复查询。补全并发最多两项，期间显示“封面加载中”；未找到匹配图片时仍显示真实的空封面状态。服务器拒绝图片时不修改请求头或绕过限制。

分类目录即使已有缓存不足 48 项，也先返回已有条目，再补充来源结果；不会等慢源结束才显示已有影片。提交搜索时让输入框失焦，收起手机键盘，输入过程保持正常编辑。

Android 仅缓存目录已提供的 HTTPS 图片地址。两个独立工作线程负责图片下载、采样解码和缩小至不超过 540 × 810，避免图片占用 API 工作线程。缓存位于应用 cacheDir，限额 32 MB、有效期七天，超过限额优先淘汰较早下载的文件。更新无需迁移缓存，系统可以清理缓存。图片日志只记录命中、字节数和耗时，不记录地址、作品名或用户信息。

这是应用自身的缓存，不上传封面到 Supabase。冷启动仍受图片服务器与网络限制；命中本地缓存才减少重复下载。原生 WebView 的首次下载、暖缓存和耗电收益需要实机验证，不能用桌面 HTTP 测速代替。

参考 [web.dev 图片优先级与 LCP](https://web.dev/articles/optimize-lcp) 和 [Android 位图缓存](https://developer.android.com/topic/performance/graphics/cache-bitmap)。采用可见位置调度和有限缓存是针对现有 WebView 架构的实现选择，不代表这些文档验证了本应用的速度。

## 手机控件

普通点击切换控件显示；双击只播放或暂停。控件提供左下角播放键、右下角全屏键和进度条。右侧长按临时两倍速，松手恢复原速度。横拖预览位置，松手只定位一次；一整屏对应 60 秒，10% 屏宽约六秒，结束位置受影片时长限制。纵向滑动保留页面滚动。直播或未知时长不能横拖定位。

手机关闭原生 video controls，仅保留一套控件；电脑保持原有控件与键盘操作。触控模拟只能验证事件逻辑，不能替代安装包中的真实触屏和系统全屏检查。

## 账号与 Windows 启动

账号初始化、网络请求和登录都有时间上限；失败显示明确提示并恢复按钮。Auth 状态回调不等待其他 Supabase 操作，避免回调中的会话锁等待。登录失败不清除收藏、历史或现有会话，不降低数据库隔离规则。

Windows 启动后检查自己的回环后端是否读取实际 userData/data 中的已启用来源，避免配置存在但服务为空时静默显示空目录。测试必须检查实际安装的用户目录，测试目录不能作为实际安装验收的替代。浏览器会话不会复制到独立客户端；真实密码登录必须由用户在客户端完成。

0.6.6 在本地服务的启动入口中明确传入配置目录、资源目录和端口，再导入配置读取模块；来源文件路径在模块初始化时固定。验证同时覆盖普通启动，不只依赖调试器启动的结果。
