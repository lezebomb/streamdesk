# StreamDesk 0.5.0 验收报告

验证日期：2026-10-13，Asia/Shanghai。上一版本报告归档为 performance-0.4.md；本文不把旧测量改称本轮重新测试。网络、缓存和并行验证影响实际时间。

## 修复与加载

原先每来源只读取一个小页，随后隐藏无评分影片；去重又发生在语言筛选前，可能选中错误配音版本。现在类型多选按 AND 交集，明确国语 / 粤语版本名称优先于来源复制的语言字段，只用真正的分类字段；解说、预告和短剧不混入普通分类。未评分影片保留在高分排序末尾。来源字段本身仍可能错误，评分没有逐部向豆瓣实时核对。

同一“动作 / 英语 / 2026 / 高分”真实 API 样本得到 86 个去重候选，界面默认显示 48 张卡片；不是宣称完整全网片库。类型“动作 + 剧情”代表场景有 16 个匹配。返回不足 48 时不编造或放宽筛选。

最后一次桌面回归：已缓存电影分类首批 47.30 ms、完整响应 48.72 ms、48 张卡片；跨筛选元数据索引在 335.29 ms 显示上述高分筛选结果，后台补查到 12.05 s 截止。缓存快不代表所有冷请求都快。此前无缓存分类首批 2.62 s、完整 8.80 s；最慢筛选完整补查仍可能耗时约 12 s，已记录，没有隐藏。

“怪奇物语4”本轮真实结果包含 11 个相关作品，第四季第一，第一 / 二 / 三季与其他相关作品随后。冷查询首批 1.96 s、完成 6.58 s；缓存回归首批 23.24 ms、完成 25.19 ms。更早的一次 API 独立基线全量搜索 11.19 s、缓存 7.95 ms；筛选 9.45 s、缓存 16.05 ms，见 api-0.5.json，不能混同于首张卡片时间。

默认分类 48、推荐 18；加载更多先显示已有候选，再继续读取。已显示卡片保持顺序和 DOM，迟到来源补在后面，不整体替换海报。高分空缓存先等收集完成再展示排序；已有同条件或跨条件索引时立即显示缓存批。高分是已索引 / 已载入数据的排序，不是完整豆瓣排行榜。

API 全局每请求并发 3，搜索每来源最多 3 次，分类每来源最多 4 页且截止 12 s。各来源先轮流读取，实际游标不因失败推进；足够候选时停止新增请求。在途同请求合并，一个消费者取消不影响其他仍等待的消费者。目录缓存持久化、有限容量、15 分钟过期；部分故障只短缓存 30 秒。缓存不持久保存播放地址或媒体，详情仍单独短缓存与健康检查。

## 新片源：如意

依据 [如意公开帮助](https://www.ryzy3.tv/help/)验证实际 JSON 接口，未改写旧域名或伪装请求头。新的默认來源总数 7；不同域名和分发路径不证明运营方绝对独立。年份参数普通试验被忽略，因此该源使用客户端核验，不虚称支持原生年份筛选。

按作品 ID、年份、正片身份选中指定动漫 2025 版、流浪地球 2019 正片、怪奇物语第四季 2022，真实首分片 **3/3 成功**。三个实际浏览器场景 **3/3 成功**：

|---|---:|---:|---:|---:|
| 我们不可能成为恋人，2025 | 4.57 s | 1920×1080 | 0 ms | 0.42 s |
| 怪奇物语第四季 | 4.41 s | 1080×608 | 169.20 ms | 0.57 s |
| 流浪地球正片 | 4.38 s | 1920×756 | 0 ms | 0.56 s |

每场景约 20 秒正常观看后验证键盘 / 快进，不算整集稳定性。怪奇物语短样本的少量等待完整保留，不写成零卡顿。API 延迟与真实分片下载结果分开记录，尺寸来自实际解码，不称缩放为原生 4K。

初次候选探测挑中了恋人续篇和流浪地球解说，匹配过宽；原始文件保留，但不把这两条算为正片验收。后续用 canonical ID + 年份 + 排除解说 / 预告重新验证通过。两部先行浏览器样本本身使用正确身份。新增流浪地球浏览器样本证明电影正片可播。

非凡三条媒体 HTTP 403，索尼公开 snm3u8 接口返回“不支持搜索”，均未加入默认来源，也未绕过限制。X / Reddit / bilibili 的分享只用于找线索，再看站点自己文档和真实媒体；Ani.pm 开发地址返回 SPA 落地页，未确认可用接口，不假定它已接入。文档线索见 [非凡](https://ffzy5.tv/help/)、[索尼](https://suonizy.net/help/)。

## 键盘、账号和数据

真实播放验证右箭头短按 +5 秒、长按 350 ms 后临时 2×、松开恢复原 1.25×、空格暂停 / 播放。输入框 / 选择框不抢键；暂停、切片、失焦时恢复倍速。ABR、进度、自动换源与画质增强核心保留。

邮箱确认、用户自行设置密码、真实邮箱密码登录均完成。应用收藏和观看记录实际写入独立 Supabase Free 项目，不仅做 UI 演示。真实回滚事务测试证明：其他用户数据不可读、跨账号写入被拒、旧修改不能覆盖较新进度。Security / Performance Advisors 均零告警。密码、令牌和用户邮箱不出现在公开汇总。首次默认邮件链接已失效的失败保留，准确回跳和错误提示已修复；不将确认邮箱等同于登录成功。

实际云端读写和客户端合并测试已通过；初次发布时手机未连接。后续 Mate 60 实机补充验证了电脑收藏到手机、手机播放历史到用户已经登录的电脑页面，详见 mobile-0.5.md。默认 Supabase 邮件只向团队邮箱发送且 2 封 / 小时；个人所有者账号可用，其它邮箱需配置 SMTP。未开通付费产品或升级套餐，免费额度和暂停限制见 docs/cloud.md。
