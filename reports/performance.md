# StreamDesk 0.3.0 性能与可播性报告

日期：2026-10-12。基线 0.2.0 完整保留于 performance-0.2.md。本轮为 PWA，不开发独立客户端。

## 长时与故障

速播初次关闭自动换源的长测在约 12.36 分钟中断；请求 plist133.ts 返回连接关闭/超时，未获得明确 HTTP 错误。随后同 URL 的普通 Node 请求 200，故归类为“网络或上游连接，原因未确定”，不能推断 DRM/播放器解码问题。原始失败 JSON 与截图保留。红牛另一轮出现短缓冲，随后因会话中断未完成 30 分钟，不计成功长测。

速播后续复测 30.12 分钟，媒体推进 1806.60 秒，0 次 waiting，自动换源开启但实际换源 0 次；这次成功不能消除先前失败。增强最终状态 off，GPU路径均值 0.30 ms。

跨新增来源故障测试：对实际速播资源的清单注入 404，切至 guangsu 的真实媒体，保留同一集和 737 秒进度，恢复到 739.80 秒。此项故障是合成的，不能标为来源自然故障。

Native 掉帧计数包含启动与截图等阶段，不是增强画布的独立呈现计数；回调/提交成本另列。Intel 的 60fps 低清样本触发保护并关闭增强，保留该结果。实际滤镜不是在所有条件下强行常驻。工作集是多个浏览器进程之和，可能重复计共享页。CPU按单核 100% 归一，不是整机百分比。

手机均衡 1080p 长测 10.09 分钟，推进 605.36 秒，0 次卡顿，增强最终仍开启。浏览器主进程 CPU 均值约 115.28%（单核=100%，不是全系统/所有子进程），另做 60 秒原画主进程观测，CPU 均值 76.82%；时长与位置不同，差值不作为纯增强增量。电池温度 34.0→36.0°C。USB 同时充电，无法分离充电、解码与增强造成的发热，电量变化不能推算播放功耗；不是 CPU/GPU 结温。手机默认关闭/自动轻量策略保留，不把这个高端手机推广到低端设备。

## 实际画面与兼容性

同一暂停帧对比使用桌面固定帧和手机 ADB 真实屏幕。手机 CDP 离屏截图无法可靠捕获暂停的 WebGL 画布，失败截图未用作效果证据；改用真实屏幕采集。可见变化较轻：平坦区域噪声略平滑、边缘细节可能更柔和，不能据此声称恢复真实细节。无高清真值，不提供虚假的 PSNR/“4K恢复率”。

- 桌面对比：reports/runs/enhancement-visible-intel 与 enhancement-visible-rtx 的 same-on / same-off.png。
- 手机对比：reports/evidence/mobile-physical-visual/on.png 与 off.png；暂停进度相同，原生控制层外区域才适合比较。
- Chrome Windows、Huawei Browser Mate 60 经过真实测试。Edge/Firefox/Safari 与其他手机仅按官方能力文档调研，未实机覆盖。

32 单元/合同测试、8 原 E2E、3 渐进搜索/分组场景、增强开关/快进、5 画质场景、5档真实 ABR 0→1、跨CMS换源均通过。2160p 是 Apple 官方 AV1 原生测试流；增强对它保持原画，没有伪造 4K 档位。

## 打包与复现

修复干净仓库打包依赖未提交 research/及本地 provider 报告的问题。必要源码、后端、shared、vendor、配置模板、已构建 dist 和许可显式进入包；raw evidence 可选，不再是打包前提。package-smoke 验证无 research/raw报告/运行时 npm 依赖的包能启动并返回目录 API。CI Windows/Linux 均运行该检查。

复现：npm ci → npm test → npm run build → npm run test:package。新增覆盖使用 TEST_SOURCES=data/expansion-verified.json、TEST_WORKS=data/expansion-works.json 与新的 RUN_DIR；原测试默认路径仍兼容。桌面增强用 bench:enhancement，手机通道见 docs/validation-0.3.md。

跳过其余 28 部作品逐一 45 秒重复播放、所有集数/分组、多小时热稳定、低端实机和其他浏览器穷举；它们对本轮关键路径收益较低或没有硬件。没有把跳过项计成功。源服务器/网络超时无法明确区分时保留 unknown；合成故障、会话中断、浏览器截图问题与来源自然故障分开记录。
